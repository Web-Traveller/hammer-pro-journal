# Hammer Pro Journal — Architecture & Domain Knowledge Memory

---

## 🏗️ 1. Modular Hook Architecture
- **`src/hooks/useTradingState.js`**: Core state orchestrator. Manages active views, date locking, modals, deferred sync queue, and timezone settings.
- **`src/hooks/useAccountState.js`**: Handles multi-account lifecycle (CRUD for trading accounts, active account selection, color coding).
- **`src/hooks/useImportHandlers.js`**: Handles broker log validation, manual session creation, OCR screenshot pairing, and date locking.
- **`src/hooks/useScreenshotHandlers.js`**: Handles screenshot compression, IndexedDB / LocalStorage storage, deletion, and lightbox modals.
- **`src/hooks/useAnalyticsMemos.js`**: High-performance memoization for daily stats, monthly calendars, ECN analytics, stock performance matrices, and equity curves.

---

## 🗂️ 2. Multi-Account Storage Namespacing
To prevent data bleed across trading sub-accounts (e.g. *Main Account* vs *Premarket Scalping*):
- **Main / Default Account**: Uses standard keys `trading_log_{date}` and `trading_journal_{date}` (100% backward compatible).
- **Sub-Accounts**: Uses scoped keys `trading_log_{accountId}_{date}` and `trading_journal_{accountId}_{date}`.
- Storage methods in `src/services/storageService.js` (`retrieveAllLogs`, `persistLog`, `removeLog`, `loadJournalFromStorage`, `saveJournalToStorage`) strictly accept `accountId`.

## 💰 3. Manual Summary P&L & Fee System
- **Primary Input**: **Gross Realized P&L ($)** (the market-close figure).
- **Shares Input**: **Total Shares Traded** (used for dynamic fee calculation).
- **Dynamic Fee Calculation**:
  - `fees = enableFees ? (roundTripShares × feePerShare) : 0`
  - `Net Realized P&L = Gross Realized P&L - Fees`
- **Pre-Import Confirmation Modal**: Always displays **Gross Realized P&L** prior to persistence.
- **Session Deep-Dive**: Displays `Net Session P&L: +$XX.XX`, with subtext `Gross: $XX.XX • Fees: $XX.XX`.

## ⏱️ 4. Scalper Trade Merging & Date Lock Rules
- **Scalper Partial-Fill Merging**: In `src/parser.js`, executions for the same ticker are merged into a single round-trip trade only if:
  1. Executed within a **10-second** window (`<= 10000ms`).
  2. Entry prices match within **$0.01 tolerance**.
  - Rapid trades entered/exited >10 seconds apart remain distinct FIFO trades.
- **Permanent Date Lock**:
  - Manual date selection sets `userLockedSessionDateRef.current = true` and `isDateManuallyLockedRef.current = true`.
  - Window focus, cloud sync, or log updates will NEVER override the user's picked session date.

## 📱 5. Platform-Decoupled Version Gating (Desktop vs. Mobile)
In `src/services/versionService.js`, desktop and mobile versions are 100% independent without legacy global fallbacks:
- **Desktop (Windows / Mac)**: Evaluates `latest_version_desktop`, `min_version_desktop`, and `download_url_desktop`.
- **Mobile (Android APK / Web)**: Evaluates `latest_version_mobile`, `min_version_mobile`, and `download_url_android`.
- **Sanity Rule**: `latestVersion` is guaranteed `>= minVersion`.
- **7-Day Hard Expiry**: Outdated builds are allowed a 7-day grace period before mandatory lock.

## 📢 6. Global Admin Broadcast Banner System
Admin can broadcast messages to users via Supabase `app_config` table with `key: "broadcast_announcement"`:
```json
{
  "id": "notice_id",
  "active": true,
  "title": "⚡ Announcement Title",
  "message": "Notice body text",
  "type": "info",
  "link_url": "https://...",
  "link_text": "Action Text",
  "allow_dismiss": true,
  "target": "all"
}
```
- Dismissing stores the ID in `localStorage` under `hammer_dismissed_broadcast_id`.
